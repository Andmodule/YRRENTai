# Цены → Скидки: акции Booking.com через Zodomus

Скидка в RentAI = акция Booking «Basic deal» на каждом выбранном объекте. Базовые цены не меняются: Booking показывает гостю старую цену зачёркнутой. Код: `backend/src/pricing/`, разбор ответов Zodomus: `backend/src/integrations/zodomus/zodomus-promotions.util.ts`.

## Как устроено

| Часть | Что делает |
|---|---|
| `price_promotions` | Скидка (кампания): процент, даты проживания, дни недели, статус, источник (`rentai` / `booking` — найдена в экстранете) |
| `price_promotion_targets` | Объект внутри скидки = одна акция Booking: id акции, желаемое/фактическое состояние, ошибка, статистика |
| `price_promotion_events` | История: кто и что сделал, что ответил Booking |
| `property_pricing_settings` | Минимальная цена, уровень Genius, доступ к акциям (вкладка «Минимальные цены») |
| Очередь (`PromotionQueueService`) | Отправляет изменения в Booking по одному объекту, с паузой и повторами (1 → 60 мин, до 6 попыток). Состояние хранится в БД — переживает перезапуск |
| Сверка (`PromotionSyncService`) | Раз в 30 мин читает `GET /promotions` по объектам: доступ, статусы, статистика, скидки из экстранета. Только чтение |

Название акции в экстранете Booking — служебная метка `RentAI xxxxxxxx-N` (Zodomus принимает не больше 20 символов: «Name string cannot be longer than 20 chars»); понятное название хранится в RentAI. Защита от дублей: перед созданием RentAI ищет активную акцию с такой меткой и, если находит, не создаёт вторую.

Статус «Включена» объект получает только после того, как акция найдена в списке Booking (сразу после отправки или при очередной сверке). До этого — «Не подтверждена Booking»; если сверка перестала её находить, подтверждение снимается. Скидка, которая не ушла ни на один объект, в списке помечена «Не на Booking», а в календаре — перечёркнутым значком с причиной.

Правила Booking, которые учтены:
- акции одной категории не складываются — гость видит самую большую (предупреждение о пересечениях);
- Genius применяется первым, затем наша скидка;
- Mobile rate и Country rate из экстранета — другая категория: они не конкурируют с нашей скидкой, а ложатся поверх неё и Genius (между собой не складываются — берётся больший). Защита минимальной цены считает по самой низкой цене: цена × Genius × наша скидка × больший из Mobile/Country rate. Размер RentAI берёт из акций, найденных сверкой (`pricing-targeting.util.ts`); такие акции не считаются «пересечением»;
- изменение акции снова делает её активной — поэтому при изменении объекты, выключенные вручную, не трогаются, а сама смена параметров = новая акция + выключение старой;
- прошедшие даты Booking не принимает — если начало уже прошло, отправляем с «сегодня» по часовому поясу объекта.

## Флаги

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ZODOMUS_PROMOTIONS_ENABLED` | `false` | Выключено: нет фоновых задач, API отвечает 503 (кроме `GET /pricing/status`) |
| `ZODOMUS_PROMOTIONS_DRY_RUN` | `true` | Только чтение из Booking; что было бы отправлено — пишется в историю. Запись = `ENABLED=true` **и** `DRY_RUN=false` |
| `ZODOMUS_PROMOTIONS_PROPERTY_ALLOWLIST` | пусто | Пилот: через запятую UUID объектов RentAI и/или номера объектов в Booking (как в экстранете), только им разрешена запись. Объект вне списка в скидку не попадает — форма показывает это до запуска. Выключение не блокируется |
| `ZODOMUS_PROMOTIONS_CHANNEL_ID` | `1` | Канал Booking в Zodomus |
| `ZODOMUS_PROMOTIONS_SYNC_MINUTES` | `30` | Период сверки |
| `ZODOMUS_PROMOTIONS_QUEUE_INTERVAL_SECONDS` | `60` | Период очереди (после действий пользователя очередь запускается сразу) |
| `ZODOMUS_PROMOTIONS_GAP_MS` | `2000` | Пауза между объектами (плюс общий лимит `ZODOMUS_MAX_REQUESTS_PER_MINUTE`) |
| `ZODOMUS_PROMOTIONS_VERIFY` | `true` | После создания прочитать акцию обратно и проверить номер/процент |

## Порядок включения на проде

1. Деплой кода (флаг выключен — ничего не меняется).
2. Миграция `1778300000000-pricing-promotions` (`pnpm --dir backend migration:run`). Только новые таблицы, есть откат.
3. `ZODOMUS_PROMOTIONS_ENABLED=true`, `DRY_RUN=true` (по умолчанию). Проверить: вкладка «Минимальные цены» → «Проверить доступ к акциям»; создать тестовую скидку — в истории появится «Пробный режим: создали бы…», в Booking ничего не уйдёт.
4. Пилот: `ZODOMUS_PROMOTIONS_PROPERTY_ALLOWLIST=<uuid объекта или его номер в Booking>`, `DRY_RUN=false`. Скидка −5% на неделю на этом объекте. Проверить в экстранете Booking (Акции) и на сайте Booking цену, в т.ч. для Genius.
5. Убрать allowlist — включено для всех.

## Экстренное выключение

Выключение флага **не снимает** уже созданные акции на Booking — оно только останавливает RentAI. Порядок:
1. В RentAI «Выключить для всех» на нужных скидках (или `POST /api/v1/pricing/promotions/:id/deactivate`) — при `DRY_RUN=false` очередь выключит акции на Booking.
2. Убедиться в истории, что Booking подтвердил выключение.
3. Затем, при необходимости, `ZODOMUS_PROMOTIONS_ENABLED=false`.

Если RentAI недоступен — акции выключаются в экстранете Booking (раздел «Акции»).

## API (`/api/v1/pricing`, роли OWNER, MANAGER)

- `GET /status` — включено ли, пробный режим, пилот.
- `GET /properties` · `PATCH /properties/settings` · `POST /properties/access-check` · `GET /properties/:id/price-today`
- `GET /promotions` · `POST /promotions/preview` · `POST /promotions` · `GET /promotions/:id` · `PATCH /promotions/:id`
- `POST /promotions/:id/deactivate` · `POST /promotions/:id/activate`
- `POST /promotions/:id/properties/:propertyId/(deactivate|activate|retry)`

## Что проверяется на пилоте (песочница это не показывает)

Песочница Zodomus отвечает фиксированными данными и принимает почти любой запрос. Проверено в песочнице 2026-10-04/05 через код бэкенда (`ZodomusService`): создание (`status.promotionId`), список, выключение, повторное включение; найдено ограничение имени в 20 символов. На живом объекте нужно подтвердить:
- формат `rooms: [{ id }]` / `parentRates: [{ id }]` и `minStayThrough: "0"` в `POST /promotions`;
- что `GET /promotions` возвращает и акции, созданные в экстранете;
- доступ: у технического аккаунта Zodomus есть права на Promotions API, а подключение объекта к Zodomus включает тип «Promotions» (иначе 403 / `HOTEL_INELIGIBLE` — объект помечается «нет доступа»);
- как скидка складывается с Genius на этом объекте.

## Автоправила (Цены → Автоправила)

Автоматические скидки «чем ближе заезд, тем больше» — **лесенка акций Booking «Last-minute»** (горящее предложение), созданных один раз на несколько месяцев вперёд. Booking сам включает нужную ступень по мере приближения заезда: расписания и повторных запросов к Zodomus нет. Включается **отдельным флагом**, по умолчанию выключено: `ZODOMUS_PROMOTIONS_AUTORULES_ENABLED=true` (нужен и `ZODOMUS_PROMOTIONS_ENABLED=true`). Код: `pricing-rules.*.ts`, `promotion-executor.service.ts` (ветка `last_minute`).

| Часть | Что делает |
|---|---|
| Правило | Группа шагов с общим `externalMeta.rule.groupId`. Миграции нет: параметры шага лежат в `price_promotions.externalMeta` (`rule`, `lastMinute {unit: day\|hour, value 1–1000}`, `bookTime {start, end}` — часы 0–24 по времени объекта) |
| Шаг | Обычная строка `price_promotions` (`promotionType='last_minute'`) со своими целями по объектам — очередь, проверка, история, сверка общие с обычными скидками |
| Запрос в Booking | `POST /promotions`, `type: last_minute`, `lastMinute`, при необходимости `bookTime`; `book_date` для такого типа не передаётся. Период проживания — от сегодня на `horizonMonths` (3/6/12); перед концом RentAI напоминает продлить («Изменить» создаёт новое правило, старое выключается) |
| Обычные скидки | Не затронуты: отпечаток (`promotionHash`) для них прежний, иначе работающие акции были бы пересозданы |

Что важно знать:
- Скидки Booking не складываются — гость видит самую большую. Шаги должны расти к заезду; форма предупреждает, если шаг «не будет виден».
- Если флаг выключить, новые шаги **не отправляются** (состояние «Пропущен», код `AUTORULES_DISABLED`; уже работающий на Booking шаг не трогается), но правила остаются **видны и выключаются** (список, «Выключить» у правила и у объекта работают при выключенном флаге; создать, включить и отправить нельзя — 503).
- Пока `DRY_RUN=true`, правило только считается (в истории — отправляемый запрос). После перехода на боевой режим на правиле появляется «Отправить в Booking» (`POST /pricing/rules/:groupId/resend`) — отправляются только шаги в состояниях «тест / ошибка / пропущен»; выключенные вручную объекты остаются выключенными.
- Защита минимальной цены проверяется по каждому шагу отдельно и только по ближайшим 120 ночам: слишком большие шаги для объекта пропускаются (`BELOW_MIN_PRICE`), остальные работают. Для правил на 6–12 месяцев цены дальше 120 ночей не проверяются — минимум стоит пересматривать.
- Для шага проверка `verify` строгая: если Booking вернул акцию не типа `last_minute`, без «за N», с другим размером или (когда часы заданы) без часов бронирования — `MISMATCH`. Такой шаг RentAI **сразу выключает на Booking** и ставит ему ошибку `RULE_MISMATCH`: иначе скидка действовала бы шире, чем задано, а при лесенке из многих шагов гость весь день получал бы самую большую. Если выключить не удалось, шаг остаётся «включён» с предупреждением «выключите в экстранете».
- «Изменить» = создать новое правило и выключить старое. Очередь всегда обрабатывает выключения раньше включений, поэтому старый шаг гаснет сразу, как до него доходит очередь (новые шаги идут по одному объекту с паузой, большие правила — десятки минут). Если выключить старое не удалось, ответ содержит `warnings`. Даже правка одного названия пересоздаёт акции на Booking.
- Объекты, выключенные у правила вручную, при «Изменить» не включаются обратно.
- **Не проверено на боевом Booking** (песочница Zodomus отвечает фиксированными данными): от какого времени Booking считает «часы до заезда»; принимает ли аккаунт `last_minute` с `bookTime`; лимит числа акций на объект; максимальная длина периода проживания. Первую проверку делать на одном объекте (allowlist), одним шагом −5%, и сверить в экстранете Booking: тип, «за N», часы бронирования, даты. Если `verify` пишет `MISMATCH` — Booking сохранил не то, что отправили.
- В календаре и на карточке объекта шаг с часами бронирования показывается только пока он действует (по времени объекта).

API (`/api/v1/pricing/rules`, OWNER и MANAGER; при выключенном флаге — 503): `GET /` · `POST /` (`replaceGroupId` — изменить правило: создать новое и выключить старое) · `POST /:groupId/(deactivate|activate|resend)` · `POST /:groupId/properties/:propertyId/(deactivate|activate)`.

Откат: `ZODOMUS_PROMOTIONS_AUTORULES_ENABLED=false` останавливает отправку новых шагов, но **не снимает** уже созданные акции. Их выключают кнопкой «Выключить» у правила или у объекта (работает и при выключенном флаге, нужен `DRY_RUN=false`) либо в экстранете Booking (раздел «Акции», имена `RentAI xxxxxxxx-N`).

Нагрузка на Zodomus: шаг — это 3–4 запроса на объект (цена для защиты минимума читается один раз на все шаги правила и хранится 5 минут). Все запросы идут по одному через общий ограничитель, поэтому правило из 24 шагов занимает очередь на 4–5 минут на каждый объект. Ответ, который RentAI не смог распознать, повторяется 2 раза, а не 6; если Booking просит подождать (`RATE_LIMITED`), остаток пачки ждёт следующего прохода очереди.

### Лесенка по часам

В форме правила кнопка «Лесенка по часам» строит шаги сама: часы бронирования «с — до», новый шаг каждые 1/2/3/4/6 часов, начальная скидка и прибавка, общий срок «за сколько до заезда». Получаются обычные шаги (по одной акции Booking на отрезок времени, отрезки идут встык) — их можно править вручную. Лимит шагов — 24, чтобы помещался целый день с шагом в час.

Точнее часа и целого процента сделать нельзя: `book_time` у Booking — целые часы. **Не проверено на боевом Booking:** сколько акций он разрешает держать на объекте (24 шага = 24 акции на объект).

## Заполненность (Цены → Заполненность)

Подсказка скидки по тому, сколько ночей сдано. RentAI считает брони объекта на ближайшие N дней и сравнивает с порогами владельца («сдано меньше X% → скидка Y%»). **Сам в Booking ничего не отправляет:** «Применить» создаёт обычную скидку (`POST /pricing/promotions`) на этот срок — со списком пилота, защитой минимальной цены, очередью и статусом, как у любой другой.

Включается **отдельным флагом**, по умолчанию выключено: `ZODOMUS_PROMOTIONS_OCCUPANCY_ENABLED=true` (нужен и `ZODOMUS_PROMOTIONS_ENABLED=true`). **Сначала миграция** `1778400000000-pricing-occupancy-settings` (одна новая таблица `pricing_occupancy_settings`, существующие не трогает; есть откат). Пока флаг выключен, таблица не читается, API отвечает 503, вкладка скрыта — выкладывать код до миграции безопасно.

- Настройки (меняются на экране): срок 7–120 дней, до 6 порогов; чем меньше сдано, тем больше скидка. Нет своей строки настроек — действуют стандартные: 30 дней; <10% → 12%, <20% → 8%, <30% → 5%.
- Сдано = ночи с бронью из календаря RentAI со всех площадок, кроме отменённых (`CANCELLED`, `DECLINED`, `NO_SHOW`). «Ровно 10%» — это не «меньше 10%». Окно начинается с «сегодня» по часовому поясу объекта.
- В списке только объекты, подключённые к Booking. Если на эти даты уже стоит такая же или большая скидка той же категории (наша или из экстранета), новая не предлагается: Booking показал бы только большую. Шаги Last-minute и Mobile/Country rate здесь не учитываются.
- Объект вне списка пилота или без доступа к акциям: скидка показана, но применить её нельзя — причина написана в строке.

API (`/api/v1/pricing/occupancy`, OWNER и MANAGER; при выключенном флаге — 503): `GET /` · `PATCH /settings`. Код: `pricing-occupancy.*.ts`, тесты `pricing-occupancy.*.spec.ts`.

Откат: `ZODOMUS_PROMOTIONS_OCCUPANCY_ENABLED=false`. Скидки, уже созданные по подсказке, — обычные скидки, выключаются во вкладке «Скидки».

## Цена для гостя (календарь объекта по месяцам)

Сколько гость **реально** заплатит за выделенные ночи на Booking и на Airbnb, строками, как в «Данные бронирования» у Booking: тариф → каждая скидка → уборка → НДС → итог; разница между площадками в %. **Ничего не отправляет ни в Booking, ни в Airbnb.** Цены Booking берутся из того, что календарь уже получил (`otaNightlyPrices` — Standard, `otaNightlyPricesFromOpen` — самый дешёвый тариф из открытых для продажи), лишних запросов к Zodomus нет.

- Booking, «самый выгодный»: самый дешёвый тариф → Genius (настройка объекта) → скидки, которые RentAI не видит и которые ввели руками в профиле → акция, которую видит гость → Mobile / Country. «Обычный гость»: Standard → акция. Уборка без скидок; НДС — только с номера (сверено с разбивкой Booking 2026-10-22: 284 → 241,40 → −45,87 → −19,55 → −17,60, + 59 = 217,38, НДС 11,73).
- Airbnb (до подключения по API): цена ночи — введённая на дату, иначе из профиля (будни / пт–сб); скидка за неделю (7+) или месяц (28+) — только на ночи; уборка.
- Сверка: итог со скриншота площадки → сервер пересчитывает тот же расчёт сам и хранит обе суммы; расхождение > 1 % — предупреждение «есть скидка или сбор, которых RentAI не знает». Если расчёт в браузере и на сервере разошёлся больше чем на 0,01 — `guest price drift` в логах сервера.

Включается **отдельным флагом**, по умолчанию выключено: `ZODOMUS_PROMOTIONS_GUEST_PRICE_ENABLED=true` (нужен и `ZODOMUS_PROMOTIONS_ENABLED=true`). **Сначала миграция** `1778600000000-pricing-guest-price` (три новые таблицы `property_channel_profiles`, `property_channel_night_prices`, `price_observations`; существующие не трогает; есть откат). Пока флаг выключен, таблицы не читаются, API отвечает 503, панель скрыта — выкладывать код до миграции безопасно.

API (`/api/v1/pricing/guest-price`, OWNER и MANAGER; при выключенном флаге — 503): `GET /:propertyId?from&to` (≤ 120 дней) · `PUT /:propertyId/profiles/:channel` · `PUT /:propertyId/night-prices` (только `airbnb`; `price: null` — удалить) · `POST /:propertyId/observations`. Код: `guest-price.util.ts`, `pricing-guest-price.*.ts`; в браузере — `frontend-user/src/modules/pricing/lib/guest-price.ts` (держать в одном виде с серверным). Тесты: `*guest-price*.spec.ts`.

Откат: `ZODOMUS_PROMOTIONS_GUEST_PRICE_ENABLED=false`.

## Базовая цена (календарь объекта по месяцам)

Своя цена объекта за ночь (за двоих) — источник правды в RentAI; цена каждой площадки считается от неё: `база × (100 + процент) / 100`, до целого. Своя цена площадки на ночь — исключение, побеждает формулу («вернуть к формуле» — убрать её). В ячейке календаря три строки: базовая · `B цена / минимум для гостя` (точка — ещё не отправлено, ✎ — своя цена) · `A цена` (Airbnb: своя → от базовой → из настроек «Цены для гостя»).

- «Заполнить из Booking» берёт текущий Standard из того, что календарь уже получил, для ночей месяца с сегодня без базовой цены — с процентом Booking 0 первая отправка ничего не меняет.
- «Отправить в Booking» — только по команде: сначала проверка без отправки («было → станет»), потом прогон того же вида, что «Открыть / закрыть даты» (`action: price`): меняется только цена, открытая / закрытая ночь остаётся как есть; не трогаются проданные ночи, ночи с бронью / блоком в RentAI, цены ниже минимальной; очередь, перепроверка, отчёт в `GET /calendar-dates/job`. Отправка только для объекта из списка пилота при `ZODOMUS_PROMOTIONS_DRY_RUN=false` и включённом `ZODOMUS_CALENDAR_DATES_ENABLED`.
- Airbnb в этом этапе только считается. «1 гость −%» и «гость сверх двух +%» учитываются в «Цене для гостя», в Booking не отправляются (модель цен Booking за число гостей не проверена).

Включается флагом `ZODOMUS_PROMOTIONS_BASE_PRICE_ENABLED=true` (нужны `ZODOMUS_PROMOTIONS_ENABLED` и `ZODOMUS_PROMOTIONS_GUEST_PRICE_ENABLED`). **Сначала миграция** `1778700000000-pricing-base-price` (две новые таблицы `property_base_prices`, `property_channel_pricing`; существующие не трогает; есть откат). Пока флаг выключен, таблицы не читаются, API отвечает 503, строки и блок скрыты.

API (`/api/v1/pricing/base-prices`, OWNER и MANAGER): `GET /:propertyId?from&to` · `PUT /:propertyId` (диапазон) · `PUT /:propertyId/nights` (по ночам) · `PUT /:propertyId/channels/:channel` · `POST /:propertyId/booking/preview` · `POST /:propertyId/booking/send`. Код: `base-price.util.ts`, `pricing-base-price.*.ts`, `calendar-dates.service.ts` (`previewPrices`, `startPrices`), `calendar-dates.util.ts` (`planPriceTargets`); в браузере — `guest-price.ts` (`channelPriceFromBase`, `bookingCell`), `BasePricePanel.tsx`, `MonthGrid.tsx`.

Откат: `ZODOMUS_PROMOTIONS_BASE_PRICE_ENABLED=false`; уже отправленные цены остаются в Booking.

## Осторожно

- Не запускать локальный backend с `NODE_ENV=development` на боевой БД: TypeORM `synchronize` изменит схему.
- В тестовом аккаунте Zodomus вебхук указывает на Render — тестовые брони (`reservations-createtest`) из песочницы придут на прод.
- Тесты `src/pricing/*.spec.ts` — только юнит, без сети и БД.
